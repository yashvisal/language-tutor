## 2. Blocking for launch

"Blocking" = a stranger cannot safely use the app with real money without
it. Ranked.

**B1. A learner can talk for free by replaying a room name.**
`app/api/token/route.ts:183-184` accepts `body.room_name` from the request.
`convex/sessions.ts:32-36` finds the existing row and returns `null`
*without checking `userId`*. `sessions.ts:95-96` computes the debit as
`delta = max(0, seconds − session.secondsBilled)`, and a second worker's
clock starts at zero — so every report in the second conversation is below
the first one's high-water mark and `delta = 0`. Burn 10 free minutes in
room R, buy a pack, `POST /api/token {"room_name":"R"}`: a full session,
charged nothing, repeatable per pack. The real client never sends
`room_name` (`lib/session/livekit.ts:56-66`), so it is pure attack surface.
*Fix: delete `room_name` from the body; `sessions.start` throws when
`existing.userId !== user._id`; `sessions.debit` asserts ownership before
patching.* S.

**B2. Two tabs spend one balance twice.** The route reads the balance
(`route.ts:166-179`) and signs it into dispatch metadata; nothing reserves
it. Each worker budgets the *full* balance (`clock.py:86`), debits land at
teardown, and the ledger goes negative by (N−1)×balance. No in-flight guard
exists — `sessions.start` dedupes on `room`, which is fresh per request.
*Fix: in `sessions.start`, refuse when the caller already has an open row
(`by_user_startedAt` exists) newer than ~15 min; or a reservation entry
released on debit.* S.

**B3. Debit refs collide across job attempts, dropping revenue.**
`billing.py:69` resets `seq = 0` per `BillingClient` (per job).
`sessions.debit` early-returns on a duplicate `<room>:<seq>` **before** the
delta logic (`sessions.ts:68-75`). Any second job for the same room — a
LiveKit redispatch after a crash, or B1 — replays `room:1`, `room:2`… and
every debit is a no-op. *Fix: put the job id in the ref, or seed the
worker's counter from the room's already-billed seconds so "cumulative"
means per-room.* S.

**B4. A dropped connection keeps metering the learner.**
`RoomInputOptions.close_on_disconnect` only fires for client-initiated,
room-deleted, or rejected disconnects; a wifi drop, a tab crash, a closed
laptop is none of those. `agent.py` registers no `participant_disconnected`
handler and the clock's `is_paused` is just `state.paused` (`agent.py:391`),
so active seconds accrue with nobody in the room, the balance burns to
zero, the session holds, and only the 10-minute idle timeout ends it. Also:
the clock starts the moment the greeting is *requested* (`agent.py:333-334`),
before any tutor audio — a session where the model never speaks is still
billed. *Fix: subscribe to `participant_disconnected` → hold the clock (and
shut down after a grace period); start accruing at the first tutor audio
frame. The 08-23 audit called "no charge if the agent never spoke"
blocking; it is still unimplemented.* M.

**B5. A session that dies is silently dumped on the plan form.**
`lib/session/live-producer.ts:546-549` — `finish()` is reachable only from
the End button and `tutor.session_over`. Nothing watches `live → idle` for
any other reason: on an agent crash, a room close, or a network drop the
reducer resets (`:674-695`), corrections are gone, `sessions.finish` never
runs, `endedAt` is never set, and `sessions.history` (`sessions.ts:218`)
filters on exactly `endedAt !== undefined` — the conversation the learner
was charged for vanishes from History. Same for closing the tab: there is
no `beforeunload`/`pagehide` handler anywhere in `frontend/`. *Fix: any
learner-uninitiated `live → idle` → `finish(false)` + a visible "ended
unexpectedly" summary; `pagehide` → `finish(false)` (the mutation is already
idempotent).* M.

**B6. Still no bounded wait for the tutor, no failed state.** Verbatim the
08-23 row. `app/session/page.tsx:145` renders the stage on *room*
connection, not *agent* connection. With the worker down: token minted,
`sessions` row inserted, stage rendered, Aura idle, no clock, no transcript,
no error, forever. Indistinguishable from "the tutor is thinking". Nothing
is billed (the clock starts in the worker), but a silent first session is
fatal to a beta. *Fix: ~10 s timer from connect to the agent participant →
a failed card with retry and a way home.* S.

**B7. The tutor plays a waiter for a learner who typed "my dog".**
`prompts.py:349-353` returns `PLAN_INSTRUCTIONS` whenever *any* plan fact
exists, and `PLAN_INSTRUCTIONS` (`:106-125`) is the in-character scene block
("You ARE the other person in the scene — the waiter, the friend… A waiter
says '¿Qué le traigo?' and waits — so do you"). The plan picker now writes
only `topic`, `focusNote`, `note` (`session-preflight.tsx:19-22`);
`scenario`/`tenses`/`vocab` are never set. Every real session gets the
scene persona for a plan with no scene. Also: `prompts.py:113-115` hardcodes
Spanish ("imagina que…", "yo soy el camarero", "perfecto, gracias") against
`config.py:3`'s own rule. And `focusNote` — the most valuable thing the
learner types — never reaches the analyzer (`prompts.py:410-414` builds the
focus block from `tenses`/`vocab` only). *Fix: split the in-character block
out and apply it only when `plan.scenario` is set; a plain "what they asked
for" block for topic/notes; de-Spanish the examples; add `focus_note` to
the analyzer focus.* S — and it should go in before the prompt work in §3.

**B8. Payments: nothing exists.** No dependency, no checkout, no webhook, no
`purchases` writer, no stubs. §3.1 enumerates the pieces.

**B9. `next@16.2.6` has a published App-Router middleware/proxy bypass.**
`pnpm audit --prod`: 18 advisories (10 high), including "Middleware / Proxy
bypass in App Router", "SSRF in rewrites", "SSRF in Server Actions" — all
patched in `>=16.2.11`. `proxy.ts` is exactly the layer being bypassed; it
gates `/home`, `/welcome`, `/session`, `/go`. Backend `pip-audit` is clean.
*Fix: bump and re-run.* S.

**B10. Metering fails open on a missing env var.** `billing.py:73-75` —
`enabled` is false if `CONVEX_SITE_URL` or `TUTOR_DEBIT_SECRET` is unset,
and `clock.py:304-305` then returns silently; a 401 from Convex is a
`logger.warning` and the session continues. A prod worker with one var
wrong gives every learner unlimited free sessions and nothing pages. *Fix:
error-level log when `user_id` is present but the ledger is unreachable;
consider refusing the job.* S.

**B11. Terms and Privacy are stubs** (`app/terms/page.tsx:16-20`,
`app/privacy/page.tsx:16-18`). What they must cover, from the code: audio
is not recorded; learner speech excerpts *are* retained indefinitely in
Convex as `sessions.outcome.corrections[].original` (`validators.ts:91-98`);
sub-processors OpenAI / LiveKit / Clerk / Convex / Vercel / the payment
provider; refunds; minutes never expire; account deletion — which has no
code path (no Clerk webhook exists; deleting a Clerk user orphans `users`,
`creditLedger`, `sessions` forever). M.

**B12. Nothing stops N accounts × 10 free minutes.** The grant is per Clerk
id (`users.ts:149-162`), `/api/token` has no rate limit, signups are free
and instant. ~$0.90 per throwaway account. *Fix: Clerk dashboard bot
protection + required email verification (no code), plus a per-user
session-start limiter in the token route (`@convex-dev/rate-limiter` fits).*
S.

**B13. Zero deployment artifacts.** No `vercel.json`, no `.github/`, no
`livekit.toml`/Dockerfile, no Convex prod deployment, no `CONVEX_DEPLOY_KEY`
referenced, no Node/pnpm pin (`engines`/`packageManager`), `next.config.ts`
is `{}` (no security headers, `poweredByHeader` on). Ordering constraint:
Convex prod fails at deploy until `CLERK_FRONTEND_API_URL` is set
(`auth.config.ts:31-37`, the right failure), which needs the Clerk prod
instance first. **Sequence: Clerk prod → Convex prod → Vercel →
`lk agent create`.** M.

## 3. The three things you named

### 3.1 Billing

The seam is provider-agnostic and already built: a signature-verified
`httpAction` in `convex/http.ts` → an internal mutation inserting one
`creditLedger` row keyed on `ref` (`users.ensureUser:149-162` is the exact
idempotent pattern to copy). Balance reactivity on return is free —
`useQuery(api.users.viewer)` in the header, dashboard and dialog re-render
when the grant lands. What is greenfield:

1. **Pack catalog with ids.** `lib/billing.ts:48-52` has display strings
   (`"$1.99"`). Needs `{ id, seconds, amountCents, priceId }`.
2. **`purchases` unit.** `schema.ts:102` is `minutes`; the ledger is seconds.
   Fix before the writer exists; add the pack/price id.
3. **Checkout action** (Convex action or Next route): pack id → caller from
   `ctx.auth` → provider session → `purchases` as `pending` → URL.
4. **Webhook route** in `convex/http.ts`: raw body (`request.text()`),
   *async* signature verification (Convex has WebCrypto, not Node crypto),
   → `purchases.status = paid` + ledger grant idempotent on the payment id.
5. **Client half of buy-and-continue.** The worker half is done. The client
   is not: `study-overlay.tsx:108` refuses to close while `outOfMinutes`, so
   `tutor.resume` is never re-sent; `out-of-minutes.tsx:41-48` offers only
   "Back to home". Needs a "continue" affordance that fires the resume and
   respects the `{"out_of_minutes": true}` ack (`agent.py:813`).
6. **A failed zero-hold debit spends the same seconds twice** — fix first.
   `agent.py:380` swallows the failure; `clock.apply_balance`
   (`clock.py:186`) then budgets `active + balance` where `balance` still
   contains the un-debited seconds. Budget from the balance a *successful*
   debit returned; refuse the resume if the zero-debit never acked.
7. Secrets on the Convex deployment (the `TUTOR_DEBIT_SECRET` convention),
   refund copy in Terms (B11).

**Stripe-direct vs Clerk Billing** — integration points, not a
recommendation. Both land on the same `http.ts` → ledger seam. Clerk Billing
reuses every piece of Clerk plumbing you have (middleware, `auth()`, the
JWT template) and hands you the customer ↔ user mapping for free — but its
commerce model is **plan/subscription-shaped** (`has({ plan })`), and this
product sells non-expiring one-off packs; you would use it purely as a
payment rail + webhook, never as the entitlement system (the ledger stays
the truth). Stripe-direct (`@convex-dev/stripe` or raw) matches one-off
packs natively but adds a second identity mapping, a second dashboard, and
a second key set. Whichever grants must write **seconds**.

### 3.2 The prompt, the goal, and the Review

**Where the prompt is today.** One standing block assembled once at
`Agent.__init__` (`agent.py:126` → `tutor_instructions`, `prompts.py:358`),
never updated after. Opening is a one-shot `generate_reply`
(`agent.py:333`). Topic plan: opens in the target language with one question
(`GREETING_TOPIC_INSTRUCTIONS:157-163`) — correct. Null plan: asks what they
want to talk about, deliberately in the *anchor* language
(`GREETING_INSTRUCTIONS:176-184`, documented at `:372-380`) — the one place
the "open in the target language" rule bends; a flag, not a bug. Brevity
and talk-share policy present and strong (`TUTOR_INSTRUCTIONS:18-25`). The
30 s nudge wording is right (`:135-146`). `TUTOR_INSTRUCTIONS:23` says
"Follow their interests. Ask about what they just said" — the opposite pole
from crystallizing a goal. **No goal step exists anywhere.**

**"Support on evidence" is half-built.** `turn_seq` is published but never
read by the tutor; correction density reaches it only on a resume
(`agent.py:679-681`); the anchor-language ratio is computed nowhere; there
is no support/repair mode in the prompt, only the unconditioned single
`{anchor}` exception line (`prompts.py:39-44`).

**Where Review is today.** Generated once at session start from the plan
only (`agent.py:319` → `review.py:209-213`), memoized forever
(`review.py:147-148`), served by RPC poll (`tutor.review`) with no push
signal — the frontend stops polling at `ready: true`. Tables are
deterministic (`conjugation.tables_for`) and tested. **Consequence of the
new plan shape:** with `tenses` empty the engine falls back to
present + preterite (`es.py:86,505`) and with no scenario to
ser/estar/tener/hacer (`es.py:365-385`) — *every session today gets the same
four generic tables*, while `REVIEW_INSTRUCTIONS:305-306` still promises
material for "the situation, the topic, and the vocabulary themes they
chose", two of which are always absent. Backlog #2 (regenerate from the
transcript on hold) is not implemented. Review cost is not counted in
`usage.py`.

**Capturing the crystallized goal — three seams.** No function tools exist
anywhere (`config.py:233-246` passes none), so every option is new surface.

1. *A `@function_tool` on the agent* (`set_session_goal(goal, forms, why)`).
   The only mechanism that captures what was *agreed* rather than inferred.
   Risk: `reasoning="minimal"` (`config.py:179`, chosen for latency) makes
   realtime models weak tool-callers; a missed call means no Review at all;
   a tool round-trip invites the model to narrate it. Needs a fallback
   anyway.
2. *Structured extraction over the first 2–3 turns* — a Luna call from
   `on_user_turn_completed`, reusing the analyzer's client pattern.
   Deterministic trigger, ~$0.001, fails closed to the plan-based Review,
   testable. Infers rather than is told.
3. *No goal object; regenerate Review from the transcript on hold*
   (backlog #2 as written). Cheapest, most honest; doesn't deliver the
   "goal-driven" framing.

Recommendation: **2 as the mechanism, 3 as the second pass** — extract at
turn ~3 (or pre-seed from `focusNote` and skip extraction when the learner
already answered), regenerate at the first hold from the transcript. Add
the tool later as an upgrade once a fallback proves the shape.

**Files that change:** `prompts.py` (B7's split first; a bounded
crystallization block in the greeting; `GOAL_EXTRACT_INSTRUCTIONS` + schema;
`REVIEW_INSTRUCTIONS` takes goal + transcript; `focus_note` into the
analyzer focus), `state.py` (a `SessionGoal` on `SessionFacts` — text,
forms, source — plus the anchor-language ratio nobody computes),
`agent.py` (the trigger; hand the goal to Review, Ask, analyzer; regenerate
inside `SessionHold.apply(True)`), `review.py` (`regenerate(goal,
transcript)`; a versioned snapshot instead of the permanent memo; keep the
last good material while regenerating so the tab never empties),
`protocol.ts` + `study-review.tsx` (handle a snapshot that changes),
`tests/` (prompt assembly + coercion; add `pytest`).

**Decisions needed:** (a) capture mechanism; (b) **does the tutor say the
goal out loud?** An explicit "so, today we work on *he comido* vs *comí*?"
is a consent-shaped exchange in the opening — structurally what the arc
removal deleted on 08-24 — and under metering it is billable time not spent
practising. Silent inference avoids both but gives the learner no felt
goal. Cap it at one exchange, in the prompt and with a turn counter;
(c) language of that exchange when there is no plan; (d) regeneration
cadence — once, every hold, or every hold with ≥N new turns (each is a Luna
call); (e) push or poll for a Review that can change; (f) the goal feeds
the analyzer focus and the Ask context (it should).

### 3.3 The arc

The removal is real: `arc.py` is gone from tree and history, nothing
imports it, no timer-driven instruction updates survive except the 30 s
nudge, no consent gates in any live prompt (the greetings forbid them,
`prompts.py:153,160`). Residue, all small:

- `prompts.py:361-364` claims `update_instructions()` "survives as a seam"
  — it appears nowhere in `src/`. The nudge rides
  `session.generate_reply(instructions=…)`, a per-reply instruction, not a
  standing-instruction update. The seam phase-6 says survives is not wired;
  if the goal work wants to update the standing prompt mid-session, that
  has to be built.
- `GREETING_SCENARIO_INSTRUCTIONS` (`prompts.py:148-155`) is dead in
  practice (no scenario is ever set) — keep only if the catalogs return.
- `backlog.md` #1 is implemented but not struck through; #3's note is
  right. `backend/src/__pycache__/arc.*.pyc` is a stale untracked artifact.
- The ordinary hold has **no idle timeout** — `clock.py:217-223` checks it
  only when `_out_of_minutes`. Phase-6 asked for one on every hold; a learner
  who pauses and walks away holds the room, the worker slot, and the
  realtime socket indefinitely. M.

## 4. Important (not blocking, but a stranger would hit it)

1. **A worker crash loses the whole session's revenue.** Debits fire only
   at zero (`agent.py:380`) and in the shutdown callback (`:257`, retried
   once in-process). SIGKILL/OOM/eviction at minute 45 bills nothing; no
   cron reconciles open `sessions` rows. Now that the debit is revenue,
   "later" is now. *Fix: a periodic debit from `clock._evaluate` (every ~60
   active s — the delta logic makes it free) + a Convex cron closing stale
   rows.* M.
2. **No realtime-error path to the UI.** Nothing subscribes to session or
   model errors; no `tutor.error` attribute. If the OpenAI socket dies the
   learner sees a live stage gone silent, and the clock keeps metering. M.
3. **Mic denied / 401 / 500 surface as raw strings.** `live-producer.ts:529-537`
   pushes `err.message` into 12px destructive text under the fold
   (`session-preflight.tsx:377-381`). `NotAllowedError` is the most likely
   first-run failure and gets a DOMException; a 401 (expired Clerk session)
   says "Try again", which is wrong. S.
4. **`/session` is outside the onboarding gate.** `proxy.ts:13-18` auths
   it; the level gate lives in `app/(app)/layout.tsx:24` and `/session` is
   outside that group. An account that never saw `/welcome` can start and be
   billed with `DEFAULT_LEVEL`. S.
5. **Token route inserts the `sessions` row before minting, never rolls
   back** (`route.ts:191-236`) — a `toJwt` failure leaves a permanent orphan
   the debit fallback (`sessions.ts:81-93`) will adopt. S.
6. **No error reporting anywhere.** No Sentry, no `instrumentation.ts`. The
   design deliberately swallows errors so the conversation survives (nine
   guarded `try/except` blocks in teardown alone, every billing failure a
   warning, `live-producer.ts:994` RPC failures) — correct, and it makes the
   absence of a collector worse. Day one you are blind. S.
7. **Cost observability undercounts.** `usage.py:52` reads only the
   `AgentSession`'s own model usage (realtime + STT). Analyzer, Review
   (generated eagerly on *every* session, `agent.py:318`), Ask and translate
   each own a separate OpenAI client and contribute zero. `est_cost_usd` is
   logged and discarded — no cost column on `sessions`. Backlog #8, still
   open. M.
8. **Balance is a full ledger scan** (`users.ts:31-40` `.collect()`), called
   from the header, dashboard, dialog, token route, and twice per debit.
   Phase-5 §Data already prescribes the fix (checkpoints or a same-
   transaction denormalized balance — never independently writable). S now,
   L later.
9. **`convex/http.ts`**: non-constant-time secret compare (`:29`), no request-
   size bound, no ceiling on `seconds`, no integer check on `seq` (a float
   makes junk refs), nothing clamps the ledger at zero. A leaked secret can
   zero any known Clerk id. S.
10. **`livekit-agents` 1.6.9 → 1.6.10** contains "don't raise when
    interrupting a cancelled or finished speech" (you call
    `session.interrupt()` at `agent.py:376` and `:411` on paths that must not
    throw) and pins `openai<3` (`pyproject.toml` has `openai>=2.0.0`
    unbounded). Nothing you rely on regressed; stay off 1.7.0 (renames trace
    attributes). S.
11. **Worker concurrency/prewarm unconfigured** — bare `AgentServer()`,
    `agent.py:925`. Headroom per instance for a realtime-audio agent is
    unknown; load-test one instance before the first public link. S.
12. **`session.end()` and mic mute/unmute rejections are unhandled**
    (`live-producer.ts:500,548,563`). S.
13. **`viewer === null` disables Start forever with no message**
    (`start-session.tsx:65-68`; same shape in `app-header.tsx:44`). S.
14. **Reduced motion is respected on the landing and the plan picker, not
    on the stage.** `conversation-stage.tsx` never checks it and runs an
    infinite breathing ring (`:268-276`); `hero-utterance.tsx:51-63` and
    `study-overlay.tsx:143-146` likewise. S.
15. **Sub-`/70` text is fixed in the shell, not on the session surface.**
    `study-ask.tsx:129` `/65` is the *coach's answer*; `conversation-stage.tsx:307`
    `/55` is the pinned turn; `study-overlay.tsx:262`, `stage-grid.tsx:91`
    `/55`; several at `/50`. On white these are the sub-3:1 greys 08-23
    called out. S.
16. **The debug readout still ships on the live stage**
    (`conversation-stage.tsx:445-448`, `held · history+correction`, mono,
    bottom-right, unconditional). Listed in 08-23's "if we only fix five". XS.
17. **The `d` theme hotkey still fires mid-session** (`theme-provider.tsx:37-66`,
    mounted globally); the toggle it was a stopgap for exists now. XS.
18. **`/design-inspo` is public in production** and `design-inspo/page.tsx:16-19`
    prints a repo path. Gate on `NODE_ENV` or auth. XS.
19. **History flashes its heading for a learner with none**
    (`history.tsx:55-62` renders the `<h2>` while the query is in flight). XS.
